# 工单分派与个人通知（2026-10-25）

## 管理员操作

1. 进入“工作台 → 工单处理 → 处理人员”。维护姓名、班组、电话，可关联已有登录账号。系统不创建默认密码，也不把居民账号直接变成管理员。
2. 打开“查看 / 分派”，选在岗人员、填写要求，可选择北京时间的预约处理时间。保存后进入处理中；不再自动填“王师傅”。
3. 处理阶段可记录多次进展；选择“提交处理结果”须填写实际处理方式与结果，提交后进入待确认。
4. 居民核对后确认或填写原因退回；管理员可在核实后写明原因代确认。未填写结果的历史待确认工单须先退回补齐。
5. 处理中可以改派；待确认须先退回，已完成禁止继续修改。有未完成工单的人员须先改派或结单，才能停用或换绑账号。

## 处理人员与居民

- 关联的处理账号重新登录后可见工作台，只列出本人分派任务，可填写进展及结果，无管理人员、知识库或民情分析权限。
- 没有登录账号的外部处理人员可建立档案，由管理员代录反馈，审计明确标记“管理员代录”；不宣称人员本人执行了系统操作。
- 居民在“我的工单 → 详情”查看处理人、班组、电话、预约时间、进展和结果，待确认时可确认或退回。
- 旧工单和旧姓名保留，未关联人员档案时明确显示历史状态，管理员须选择真实档案后继续反馈。

## 个人通知

- 搜索按钮继续做全局检索；铃铛打开独立通知面板。
- 用户 ID 从服务端会话获取，不接受客户端指定通知收件人。
- 工单提交、分派、改派、进展、待确认、确认、返工通知相关居民及关联处理人员；新工单通知管理员，各账号独立已读。
- 报名成功、已报名活动安排修改、当天有效的倒计时进入本人通知。过期倒计时不计入当前通知及未读数。
- 提供未读角标、只看未读、单条及全部已读。最多展示最近100条有效记录；未读数按全部有效通知计算。
- 面板打开、页面切回可见以及可见页面每分钟刷新；业务操作后刷新。退出或切换账号清空客户端状态，不把通知正文存入浏览器本地存储。
- 本次为站内通知，无短信、微信或操作系统推送。

## 实现与升级

- `workflow.py`：权限、人员档案、工单动作、通知接口。
- `operations_schema.py`：schema v5，增加 service_staff 与 notifications；工单新增 assigned_staff_id、resolution、due_at、version。
- 使用已有管理员 / 居民角色，处理权限来自启用的人员档案关联，不改写 users 的角色约束。
- 工单动作必须带 expected_version，在现有事务与写锁内检查，旧版本返回409；前端保留错误和刷新入口。
- 处理人姓名与权限关联分别存储；前端显示控制不替代后端授权。
- 所有写动作沿用 CSRF、会话、限流与参数化 SQL。人员与通知在 SQLite 和 PostgreSQL 均持久化，启动自动迁移。
- `NotificationCenter.vue`、`TicketWorkflow.vue`、`WorkforceManager.vue` 分开组织功能，避免复用搜索面板承担通知。
