# 民情数据分析与辅助决策

## 入口

管理员登录后，切换至管理工作台 → **民情分析与决策**。

- 民情分析：近 7 / 30 / 90 天咨询、诉求走势、区域排行、类型环比和资源安排建议。
- 人房事底册：增改小区、楼栋、公共空间与巡查备注；将已注册居民关联到地点；展示人员、地点、事项与资料交接入口。
- 分析报告：生成真实数据的统计报告，保存快照，查看历史、导出 Markdown、删除报告。
- 智能助手：管理员可以输入“分析近30天社区诉求”“哪些类型的报修增加了”，由受权限校验的工具返回统计依据与建议。

## 数据与隐私

咨询分类从该功能上线后开始累计，仅记录完成对话的居民问句分类、时间和不可逆事件摘要，不保存原文或账号标识，不回填历史聊天次数。管理员测试对话不计入居民咨询。

诉求直接读取现有工单；报修文字通过明确关键词归入停车、照明、虫害、噪音等主题。分类为规则匹配，不等同于经过人工认定的事件性质。区域优先匹配底册地点名称，再按小区名称或楼栋文字归并；未匹配记录单列。

统计周期按北京时间自然日计算，包含今天；环比是前一个相同天数区间。只有标准日期参加趋势，历史“今天 / 昨天”等演示记录不会被猜测成真实日期。新增诉求按创建时间统计，完成率按这些工单的当前状态统计。两期合计不足 5 件时标注样本不足；上期为零不计算百分比。

报告由确定性统计规则生成，保留数据口径和局限，不调用模型猜测原因；建议需工作人员核实，不自动派单，不进行个人风险评分、资格判断或产权认定。底册只维护服务必要的注册账号与地点关联，不采集身份证、房屋产权或家庭敏感标签。户数为各地点手工录入的加总，若同时登记小区及楼栋，应避免重复计数，不代表自动核验的去重户数。

“查看演示效果”只替换分析图表的数据，不写入业务表，不能把演示图表保存为真实报告。真实数据为空时展示明确空状态。

## 持久化与迁移

SQLite 与 Neon PostgreSQL 均使用 schema v3，启动时在事务内增量创建：

- `civic_events`：咨询分类事件，保留近 365 天。
- `civic_reports`：最多 1000 份真实统计快照，列表显示最近 50 份。
- `civic_places`：最多 2000 个地点及网格、户数、交接备注。
- `civic_resident_links`：居民与地点关联，界面展示最近注册的最多 300 个居民账号。

迁移只创建表和索引，不删除或改写已有账号、工单、文档、会话。云端表位于原 Neon 数据库，随 Render 启动自动迁移，无需另建 Neon 项目。所有新增 API 均要求管理员；写操作沿用会话、CSRF、来源校验、参数校验与审计记录。居民账号不能访问全社区统计或底册。

## 前端动效

包含渐进卡片入场、统计卡悬浮反馈、趋势线绘制、排行进度条、雷达扫描、加载骨架和状态提示。窄屏自动改为单列；尊重系统 `prefers-reduced-motion` 设置；图表提供可展开数据表，避免只能通过悬停读取数据。

## 部署

将上述源码提交到现有 GitHub 仓库，调用 Render 最新提交部署；Neon 的增量表结构在启动时同步。实际发布版本可通过 `/api/health` 的 `features` 中 `civic-analytics` 标识确认。后续维护命令见 `RENDER_DEPLOYMENT.md`。
